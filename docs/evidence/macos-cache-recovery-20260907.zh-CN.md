## 已确认的回归链路

1. 2026-09-06 修复版 `0.4.0+codex.20260906104230` 曾真实成功。用户引用的两个
   历史任务合计有 4 条成功委派及对应的 `passed` outcome，并非此前完全没有测试。
2. 修复代码保留在独立工作树；当时本机市场仍指向主源码中的旧版本
   `0.4.0+codex.20260906095738`，缺少 macOS Codex `0.153.4` 准入修复。
3. 2026-09-07 09:57（Asia/Shanghai）旧版缓存被重建。检查时新版缓存已不存在，
   但稳定 plugin data 的 vault 中仍保留新版，活动指针也仍指向新版。
4. 原加载器只查当前缓存及同级目录，找不到活动版本便静默回退旧版；普通 Hook/MCP
   启动不读 vault。隔离测试先复现了这一故障，再验证恢复路径。
5. 缓存重建还会把已物化的绝对 Node Hook 命令还原为源码中的 bare `node`，造成
   信任哈希变化。运行时加载器发生在 Hook 获准执行之后，无法单独修复这一层。
6. 「优化邮箱注册流程」的原始任务记录没有 Router 开发者上下文注入、实际
   `route_stage` 或子代理调用；Router 数据库也没有该任务的宿主模型观测或路由。
   早于该任务的全局 Hook 诊断不能证明它的 Hook 已执行。信任配置被谁、何时替换，
   以及那次缺失注入的精确触发原因，均没有足够直接证据，不归因于用户操作。
7. 本次热更新进一步复现：当前父任务仍用最早缓存入口，子代理固定使用另一个旧
   入口，原资格绑定只保留父入口和最新清单入口。因此无工具子代理实际完成后，
   Hook 证据仍被正确拒绝为 `HOST_HOOK_SET_MISMATCH`。新增修复保留的只有历史
   成功证明中实际观察过、且现在仍通过完整定义核验的入口。
8. 最后一次当前任务子代理确实启动，但未获得 `SubagentStart` 上下文；父任务
   的 Pre/Post 与子代理 Start/Stop 四类 Router 证据均缺失。子代理只读取过一次
   工具描述元数据后停止。原生任务投影没有呈现该自定义工具调用，完整原始记录
   则包含它。因此常规无工具审计正确拒绝，必须使用独立的严格恢复审计收尾。
9. 隔离原生实验复现了旧宿主持有旧 Hook 路径：外部替换注册来源后，新任务、
   普通 resume、unsubscribe 后 resume 及 MCP reload 都不能更新路径；同一

   当前桌面工具没有暴露该入口，新启动 CLI 对自身的刷新不影响桌面进程。此实验
   证明旧路径保留问题，尚不能单独解释当前桌面完全不派发插件 Hook 的精确原因。
10. 用户重开桌面后，本任务的 Router Hook 派发恢复。新资格最初带着两个有历史

## 修复内容

- 把精确 macOS `0.153.4` 适配移入实际发布源码，保留已有 Windows 适配；未知
  版本、隐藏工具操作、身份变化或不完整原始记录仍拒绝。
- 缓存缺失时只读选择索引中活动指针指定的 vault 运行时，拒绝损坏、不兼容、
  未索引、符号链接或隔离版本。安装器同步刷新历史启动壳的加载器。
- 注册来源改为稳定 plugin data 中的受管完整副本。副本继承实际安装的 Hook/MCP
  启动定义，使用摘要和来源凭据核验。更新通过原生配置 API 的版本比较后写入，
  只替换 Router 市场表；失败时有条件回滚，保留并发修改及恢复证据。
- 后续修复、升级及冷安装从同一 canonical checkout 生成新的受管来源，避免重新
  指回未安装修复的另一个工作树。便携源码本身仍保持便携。
- 任务原有成功资格在运行时或绑定改变后，只允许重新进行固定无工具自检；不复制
  原有成功结论。旧资格精确归档，准入与归档在同一事务中完成。
- 对本次已完成但 Hook 入口不匹配的失败，只能使用显式一次性恢复命令。命令两次
  读取完整原生子代理记录，核验无工具、自身模型、父子身份和结果后，才允许一轮
  新资格验证。它不改信任、不把失败改为成功，也不直接允许普通工作。
- Hook 诊断按任务、按 turn 保存有限数量的去标识化记录。`context_emitted` 仅证明
  Hook 发出了上下文；宿主是否消费仍须查原始任务记录。新进程同时提供活动指针
  与来源诊断，避免用别的任务或旧版全局日志代替当前任务证据。
- 准入额外核对当前原生任务的最新 turn 及该 turn 的实际 Router Hook 回执。
  即使新进程清单全部已信任，若当前 turn 没有回执，也返回
  `HOST_HOOK_DISPATCH_NOT_OBSERVED`，不分配资格验证票据或子代理存储预留。
- 未消费资格票据的显式恢复支持父子 CLI 版本不同的完整原生证据。额外的
  `codex-0.153.4-tool-metadata-only/1` 适配只接受本次已审查的一个精确字面量
  `ALL_TOOLS` 查询及匹配输出，不执行 JavaScript，也不放开其他只读工具。
  它只能保留失败并释放占用，不能用于常规无工具资格验证。恢复后的 pending
  资格必须再次显式授权，并由一条新的完整原生自检证明后才能允许普通委派。
- 安装成功提示改为明确报告文件和启动探针的结果，不再直接宣称当前任务恢复。
