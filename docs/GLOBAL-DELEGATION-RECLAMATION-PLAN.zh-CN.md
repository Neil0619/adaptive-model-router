# 全局委派预留回收开发方案

## 目标与范围

2026-09-11 用户接受：全局上限从 4 调整为 10，正常流程及时收尾，满额才启动跨任务核验；优先结清已有终态，再按最后真实活动时间选择可延期的旧委派，只释放缺少的数量。仍在执行、操作不明或消息归属不明的委派不自动回收。

本次先处理用户明确指定的三条历史预留：9 月 3 日两条缺失原生关联的记录，以及「提供通用问题解决方案」已完成但轮次关联失败的记录。其他历史委派不做批量人工清理。

## 已确认问题

- 全局计数无项目或任务过滤，4 条未结算记录阻止其他任务创建子代理；错误却统一写为存储限制。
- 原生最终回复内部透传的 turn_id 可以不同于 item_completed / task_complete 的原生轮次 ID。当前解析器错误地假定它们相同。
- 任务归档会移动原生日志；保存的旧路径需要按确定的原生目录规则重新定位并再次验证身份。
- 已有宿主满额恢复按本根树运作，不能替代全局预留回收入口。
- 安装后真实验收另复现连续热升级兼容问题：新 child 首次使用前一版配置的 Hook 入口，旧资格保留逻辑仅保留实际 dispatch 入口，丢弃已验证的前一版配置入口，导致 HOST_HOOK_SET_MISMATCH。修复保留当前绑定的 parent / configured 两个角色和实际观测入口；不接纳全部历史缓存，仍需核验等价定义与真实资格证明。

## 实现设计

### 1. 预留、执行和业务结果分别记录

全局预留释放不等于业务验收完成，也不等于原生驻留对象物理卸载。增加可审计的预留释放记录，保存原始阶段引用、全部输入与每轮最终成果的加密快照（不收集推理文本）、来源、释放原因、核验摘要及责任归属。既有 outcome 不覆盖，未观测的 Stop / no_child 不补造。

用户明确指定、但原生证据缺失的历史记录允许单独解除全局预留；原任务的未决 gate 与证据责任保留。这是显式运维处置，不作为自动回收未知委派的先例。后续出现新启动/执行事实时重新计入容量。

### 2. 修复真实完成关联

用同一 child 的原生消息 ID、正文、final 阶段、task_started 和后续 task_complete 建立唯一关联；允许透传 ID 与原生轮次 ID 不同。冲突、错 child、不同正文、旧轮次或完成后的新输入不能得到完成证明。保留完整结果摘要及现有 memory citation 校验。

### 3. 全局满额入口

只有真实委派准入且本任务没有活动 gate 时才运行。事务内重新计算占用，缺额为 max(0, 当前占用 + 1 - 10)。

优先处理已具备核验终态且已有结果处置的记录；仍不足时按最后真实活动时间排序，对无当前执行、无未决操作、原生身份与消息记录可核对的阶段保存延期责任并解除全局预留。状态查询、维护扫描和单纯数据库更新时间不算业务活动。每释放一个重新核对缺额，足够即停止。

自动延期保留原阶段的待办和恢复保护，不能把原阶段自动标为 passed。恢复任务时展示延期原因和原始材料，先解决原阶段收尾责任，再按正常路由开始新阶段。

### 4. 保护与并发

- 当前申请者自身活动 gate 优先，不借全局回收绕过同任务互斥。
- 活动轮次、未结束命令、未知执行覆盖、在途或归属不明消息、缺失原生证据均跳过。
- 回收判断与写入用同一 SQLite 写事务，保存证据快照；新输入或新操作使旧释放依据失效，重新占用预留。
- 已释放阶段只允许收尾维护；不能借旧 child 执行新业务。
- 恢复子代理前，在同一事务中重新取得全局预留；满额时暂缓该次恢复，不能因旧任务恢复而突破上限。主任务读取资料、查询状态或单纯建立维护意图不算子代理重新执行。
- 全部不可回收则本次暂缓委派，下次真实准入重新评估；独立审查要求仍需真实独立执行。
- 已结算阶段的历史维护另取执行预留，以维护 generation 计费。原始 attempt 被 64 条终态历史保留策略裁剪后，仍用已验证的 child / route 归属领取预留，不重建虚假启动记录。已持有预留后来出现 unknown，仍保守计费。
- 重复维护使用 journal 中首次 intent 作为非业务活动边界；查询、维护和归档均不刷新业务年龄。
- 归档与恢复按确定路径重新定位并校验身份；文件元数据变化时验证完整原文摘要，内容不变不重新占位。内容证明使用有限的进程内缓存，未持久化改写业务状态。
- 共享核验时限：普通 inventory 150 ms，实际满额扫描 1500 ms、最终核验最多再 1000 ms。超过时限按未知保留计费，状态报告 verificationDeferred，回收结果报告预算耗尽。原始输入/最终结果保留限制为 1 MiB，超过则跳过回收。
- 只读 status/history 不执行回收。

### 5. 可观测性

区分全局数量达到上限、显式字节预算超限、磁盘不足和证据不可信。状态显示上限、占用、显式释放和延期记录；返回本次回收数量及未回收的原因，不输出原始任务正文或票据。

## 验收

1. 真实 ID 不一致样本可完成；错身份、内容冲突、新轮次、未完成操作不能通过。
2. 10 条正常预留可用，第 11 条在无候选时准确暂缓。
3. 满额跨项目回收；终态优先，其次最旧真实活动；只回收缺额。
4. 全部活跃、执行未知、消息归属未知均保留；无空任务探测。
5. 多进程准入不超发、不重复释放；新活动重新计费；重复处理幂等。
6. 延期要求与部分结果可恢复，原 outcome 不变，查询不改变活动时间或触发回收。
7. 指定三条历史预留有前后快照、明确释放依据；其他记录保持原状。
8. 插件静态验证、规则评估、相关与完整测试通过；安装后检查实际运行版本和真实委派的创建、完成、结算。
