# Router 升级隔离审查

日期：2026-09-12。审查基线：`main` / `2ffccd911cd49c0a311584176aff488a56be1558`。

状态：本文保留 2026-09-12 开发前的审查基线与方案；下文代码行号和“当前”均指当时版本。后续实现、实际兼容范围、测试与误写例外见 [实现与验收说明](RUNTIME-UPGRADE-ISOLATION-IMPLEMENTATION.zh-CN.md)。首次安装仍延后。

## 结论

从当前入口和可信身份能力看，**兼容的 Router 日常更新**可以优先采用插件侧隔离设计，无需把新增宿主接口作为实施前提；是否达到已加载任务无感升级，仍须通过本文规定的双任务和两平台验收。现有机制没有做到这一点，不能靠保留旧 Hook 目录或再次增加失败重试来保证。

建议采用：**稳定 Hook/MCP 入口、候选隔离、任务绑定运行时、活动阶段固定版本、空闲边界验证后迁移、按真实引用回收**。

仅编辑开发仓库没有必要影响已安装任务；安装和全局激活应是独立的发布动作。对于宿主自身升级、Hook 定义与信任变化、冻结的工具接口变化、破坏共享存储协议的更新，不能承诺任意版本都无感切换。

## 三种方案的取舍

| 方案 | 可行性与优点 | 代价与限制 | 建议 |
| --- | --- | --- | --- |
| 整个任务永久使用创建时版本 | 概念简单，能隔离 Router 实现更新 | 长期闲置任务会保留旧代码；仍需兼容新宿主、共享数据库和旧绝对入口路径 | 不作为默认策略 |
| 每次调用立即切到最新版 | 当前实现已有 | 无法保证活动阶段始终使用一致实现；失败可能在其他任务中暴露 | 不继续沿用 |
| 稳定入口，活动阶段固定，空闲时迁移 | 可同时保护在途工作和收敛版本数量 | 需要实现统一选择、迁移协议、兼容检验与回收；存在一次入口迁移边界 | 推荐 |

## 推荐设计

### 1. 把开发、候选和正式发布分开

- 开发修改和离线测试不改已安装的运行时、marketplace 或活动指针。
- 候选包放在生产 loader **不会扫描**的目录，使用独立数据区验证。候选必须经过显式晋级，不能由任意旧任务的下一次 Hook 自动晋级。
- 发布只更新“新绑定任务可使用的默认版本”；已有任务的绑定不随全局指针改变。
- 常规运行时发布不重新注册插件，也不改写所有历史桥接文件。Hook/MCP 入口版本与业务运行时版本分离。

### 2. Hook 与 MCP 必须使用同一绑定

- 由稳定的分发入口，按受信宿主身份定位任务；MCP 的 contextId、Hook 的 session_id、子代理的可信父子关联必须收敛到同一记录。
- 任务记录运行时版本和内容摘要；创建委派票据时，将该阶段的运行时身份与票据、子代理和结果责任一起原子绑定。
- 从发票开始，覆盖 Pre/Post、Start/Stop、同阶段 followup、命令 session、维护收尾、最终 outcome。不能只固定 spawn 那一次。
- 子代理按可信父任务与票据继承绑定；不能按子代理刚创建的时间，或调用者提供的任意版本参数选择最新版。
- 历史事件交给其所属阶段的版本处理；跨任务调用要由操作所属记录选择运行时，不能按发送者版本覆盖接收者状态。

这需要修改入口分发和阶段持久化契约，当前代码没有这些保证。稳定入口自身也应小而受版本协议约束，不能继续在每次升级时覆写其依赖。

### 3. 只在可证明安全的边界迁移

默认在原生根回合结束后、下一回合业务开始前迁移；不能把两个工具调用之间的短暂空隙视为空闲。安全边界还同时要求：没有未消费票据、运行中子代理、未处理消息、未知或未结束的外部操作、待验证结果、维护收尾责任，以及尚未完成的当前版本调用。原生根回合结束也不能替代这些条件。

- 候选资格与旧有效资格分别保存。旧绑定保留，迁移期间暂停该任务的新业务 admission；候选自检仍受统一生命周期门禁约束。
- 原子切换时再次核对绑定版本和未决责任，防止核查后又接收新消息。
- 候选失败保留实际失败证据，不覆盖仍然有效的旧绑定。只有候选失败已经安全结清、确认不存在未决责任，且旧宿主/Hook/存储协议仍有效时，才恢复旧版业务 admission。不得伪造新版本通过。
- 候选未启动确认、缺失 Stop、状态未知或仍有命令/消息责任时，必须先核查和收尾；不能仅恢复旧指针绕过门禁。现有 `router.mjs` L411–417 和 `delegation-gate.mjs` L206–211 也不允许未结清 attempt 被旧资格绕过。
- 当前版本已不支持实际宿主、信任发生变化或存储协议无法兼容时，旧版本也不能作为虚假兜底；应明确报告这个升级边界。
- “这一轮回复结束”不是单独的迁移或回收证据。长期闲置但无未决责任的任务恢复时，可经稳定入口迁移，不必永久绑定创建时版本。

### 4. 区分完整性检查与生命周期能力检查

仍对每个发布包验证完整内容摘要，保持票据、身份、Hook 信任和终态校验。不能简单删掉摘要检查或把失败资格改成通过。

在模块边界明确、依赖与回归证据充分后，可以将稳定生命周期适配器的能力证明与模型策略、普通业务模块的发布摘要分开：已证明不影响生命周期的改动不必使所有任务重新创建自检子代理。宿主构建、有效 Hook 链路或相关适配器变化仍需新的证明。

### 5. 共享数据必须先证明双版本兼容

- 首阶段只准入已验证的加法迁移；旧、新 writer 在同一数据副本上交替和并发完成真实阶段流程。
- 检查字段、枚举、编码、约束、trigger、默认行为和结果语义，不能只比较表/列是否存在或契约版本号是否相等。
- 不兼容迁移暂缓发布到正在使用该数据协议的任务；必要时另行设计存储协议适配，不能通过恢复旧数据库快照丢失其他任务的新数据。
- 运行时失败回退只改变版本选择，不自动撤销已发生的共享数据写入。

## 是否会积累很多不同版本的 Hook

本次只读盘点：缓存中有 **39** 个带 runtime.json 的版本目录，文件逻辑总大小约 **52.1 MiB**；runtime-shell-vault 中有 **61** 个，约 **69.8 MiB**。两处可包含同版本副本，目录数不是同时注册或运行的 Hook 数；数字也不包含其他备份目录。

当前 vault 保留兼容版本，旧协议版本只移出活动索引，文件仍保留（`manage-install.mjs` L791–817、L890–921）。旧任务校验还要求历史入口可发现、定义等价（`hook-readiness.mjs` L178–196）。因此不能现在直接只留最近两版。

推荐设计不为每个任务注册一套 Hook。常规更新复用稳定入口，版本化的是其后面的运行时包；通常保留当前默认版本、一个回退版本，再加仍被活动阶段实际引用的版本。

回收必须核对运行中进程/调用、任务绑定、阶段、未决消息与维护责任、回退引用和宿主入口引用；不能按时间或版本数量强删。实例崩溃后的过期心跳只能触发核查，不能单独证明工作结束。

仍需承认两个限制：

1. **“无限期保留旧任务的原始执行环境”与“永远最多 N 个完整版本”不能同时保证。** 被长期保留的活动责任或无法证明已退役的入口可能使数量超过目标。
2. **既有任务保存的旧绝对路径不能凭插件愿望消失。** 在证明宿主/进程不再引用之前，要保留真实入口及其所需依赖；精简成兼容入口也必须验证，不是把旧目录随意替换为软链接。未来稳定入口可阻止每次普通升级继续新增一套宿主路径，但既有历史目录需要单独迁移和退役。

对不兼容的 Hook 注册、工具库存、宿主构建或权限/信任变化，可能需要受控重载或一次冷迁移。基于已有可用入口与原生身份信息，优先实现插件侧运行时隔离有明确的代码切入点，不需要先要求宿主新增功能；这是待实际迁移验收的架构判断，不能据此宣称宿主所有加载行为均受本项目控制。

## 实施顺序与验收门槛

1. 候选与生产发现隔离；增加“暂存不自动激活”的验证。先阻止开发验收误改其他任务。
2. 增加稳定分发与任务/阶段版本绑定，让父子与整个阶段生命周期使用一致运行时。
3. 增加独立候选资格与原子迁移；失败安全结清后恢复旧有效版本，未知责任保持门禁。
4. 建立新旧存储读写互操作测试和不兼容升级阻断。
5. 在证明绑定、入口和进程可退役之后，增加版本 GC。先保护连续性，再收敛磁盘副本。

完成标准必须同时覆盖至少两个已经加载的真实任务，不能只验收安装者自己：

- A 已发票未 spawn、A 子代理运行中、A 等待命令或消息结果、A 正待结算时，分别发布 B；A 原责任可完整结清，且没有混用版本。
- B 创建的新任务使用新版；A 在安全边界迁移；候选自检失败且已安全结清时，A 仍可用旧版执行其原本有效的流程。
- 候选已报错但缺少 Stop、状态未知或仍有命令/消息责任时，保留旧绑定，同时禁止新业务委派；核查和安全结清之后才恢复。
- 父子分别持有不同历史 Hook 快照、旧 MCP 长期驻留、任务压缩、长期闲置恢复，都使用正确绑定。
- A/B 交替与并发读写共享数据，升级进程中断、回滚、新旧调用交错，均不丢失或重复结算。
- GC 后恢复闲置任务；仍有引用的版本不得删除。不支持的新宿主或新的信任要求必须准确报告。
- 覆盖 macOS 与原生 Windows；离线模拟不能替代两平台已登录任务的验收。

## 本轮验证及范围

- 独立只读审查了资格、原生宿主、共享数据库、历史入口和回收边界；主任务核对安装器、loader、MCP 和既有事故文档。
- 临时目录实验调用生产 `resolveRuntime`：活动指针保持 A，仅放置兼容 B，旧入口就选择 B 为 provisional candidate。实验目录已删除，没有调用本机安装器或更改生产指针。
- 已执行升级、vault、安装器、Hook readiness、原生资格相关现有离线测试：**126 通过，0 失败**；数据库测试另 **5 通过，0 失败**。日志在 `/tmp/router-upgrade-isolation-review-tests.log` 与 `/tmp/router-upgrade-isolation-database-tests.log`。
- 这些通过结果确认当前实现行为及保护范围，不表示本文提出的隔离方案已实现。尤其现有热升级测试要求旧 MCP 下一次调用升级，并没有断言活动业务阶段保持版本。
- 本轮未运行实际全局升级、跨升级双任务实测或原生 Windows 登录验收，以免再次干扰用户正在运行的任务。

本轮交付为审查结果；没有安装或上线本文方案。
