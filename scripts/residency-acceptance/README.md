# 原生子代理驻留验收驱动

这些脚本由修复任务中的代理执行。它们调用已安装 Codex 的原生 App Server 和 Router，使用单独的临时任务树与 Router 数据目录；不修改用户主任务的模型或业务数据，不授予 Hook 信任，也不修改宿主程序。

## 两类验收

| 入口 | 用途 | 不能证明的内容 |
| --- | --- | --- |
| `plugins/adaptive-model-router/scripts/probe-residency-acceptance.mjs` | 固定模型响应，经实际 Router、受信 Hook 和原生工具执行同根连续阶段、补充输入与最后响应窗口竞态 | 真实模型理解要求和结果质量 |
| `scripts/probe-residency-semantics.mjs` | 真实模型执行补充要求、结果纠正、旧子代理维护、取消、延期跨轮读取及精确拒绝消息后的恢复 | 其它驱动、原任务和独立审查的覆盖 |
| `scripts/probe-residency-capacity.mjs` | 三个非 Router 原生压力样本积压消息后，验证候选票据的精确容量拒绝及同根新票据恢复 | 旧 Router 数据迁移及真实模型语义质量 |
| `scripts/probe-residency-operations.mjs` | 真实模型执行普通多输出、并行命令、预期非零退出和原生接管的补丁命令；核对进程、原始回调、自然退出或补丁终态及实际文件 | 异常人工解除、旧任务守卫与完整 P4 |
| `scripts/probe-residency-exceptions.mjs` | 实际命令创建失败、未明责任、根的原生核实、伪造引用拒绝、幂等处置及同根下一次委派 | 未复现的其它服务错误及旧任务已加载 Hook 的状态 |
| `scripts/probe-residency-shared-roots.mjs` | 同一 AppServer 和 Router 数据库的双根满额隔离、独立恢复、旧 child 实际 LRU 淘汰后同身份重载、两次补充及字节记账幂等 | 固定响应不证明真实模型理解能力，也不承诺不同原生版本的相同缓存策略 |

源码一致性、原生工具接受、当前要求的结果校验、唯一 outcome 与操作清理分别检查。任何预检查失败都不能记为原生验收通过。

操作驱动仅在自己新建的临时工作目录启用 workspace-write，用于验证被原生接管的补丁实际产生预期文件；其它驱动仍默认 read-only。该补丁用例必须同时观察到原生 Bash 开始记录、没有伪造的 Bash Post、准确的 FileChange 终态、预期文件内容和唯一结果结算。主任务的临时补丁对照或构造的日志回放不能替代此真实 child 用例。

## 代理执行顺序

在仓库根目录使用 Node 24。先审阅当前 Hook 清单；只有用户已信任当前定义，才能进入带模型的验收。

```sh
node --test scripts/residency-acceptance/checks.test.mjs
node scripts/probe-residency-semantics.mjs --preflight
node plugins/adaptive-model-router/scripts/probe-residency-acceptance.mjs --rounds=1
node plugins/adaptive-model-router/scripts/probe-residency-acceptance.mjs --rounds=100
node scripts/probe-residency-semantics.mjs
node scripts/probe-residency-operations.mjs
node scripts/probe-residency-exceptions.mjs
node scripts/probe-residency-capacity.mjs
node scripts/probe-residency-shared-roots.mjs
```

`--preflight` 即使通过也不启动模型。`HOOK_TRUST_REQUIRED` 是中止状态；不得跳过信任、写入批准哈希或把退出码改成通过。模型验收在每个驱动自己的临时任务树中执行，不把多个根任务的阶段数相加冒充“同根 100 阶段”。前一驱动清理未被证实时，不启动新的驱动。

驱动输出临时目录内的报告路径。保存报告与实际执行日志，并与安装候选版本、源码摘要、Hook 清单对应。保留有问题的具体回合及调用标识，不在观察超时后重复创建子代理或重发状态不明的操作。

## 真实模型驱动的检查

- 原生资格检查：实际模型和思考档位符合 Router 目标，真实子代理满足无工具资格探针约束。
- 同阶段补充：先交付 `a=17, b=23`，加入 `c=42` 后必须保留全部三项，结果为 82。主动要求一个遗漏原始记录的负对照，确认校验器拒绝结算，然后在原阶段纠正；这不是模型自然出错率测量。
- 实际运行中补充：启动有外部释放条件的临时原生进程，观察到未结束句柄后发送补充要求；原进程终止及全部要求的结果均核验。
- 未结束操作取消：原生进程运行时登记取消意图，再中断代理、释放测试进程并收集真实终止回执；保留原要求和部分成果。
- 旧子代理维护：已有 outcome 的缓存子代理接收收集请求。用一次只针对临时文件的命令尝试验证实际 Router 工具守卫，核对原生拒绝回执、文件不存在、最新 Stop 及无新 Start；口头拒绝不算守卫通过。
- 取消：保留原始要求和部分结果，只在收集核验后结算为失败，不能标成业务执行成功。
- 延期：下一根回合仍可读取保存的要求与部分结果；合成测试要求经过显式取消后才从待处理工作中移除。
- 已结算阶段的新业务消息：匹配实际原生 Pre 拒绝，要求保留在发送者；随后受限维护可完成，活动维护期间不准入冲突委派。未知发送错误不冒充该明确拒绝。

校验器拒绝遗漏、重复、错误总数、空要求、空部分结果、未完成操作及无关联的工具拒绝。守卫验收还必须匹配预先指定的 canary 命令；代码模式只接受严格的单一原生调用转发和实际失败响应，打印拒绝文字、成功的 Shell 输出或另一条命令均不算通过。4 项本地校验器测试通过，只证明这些校验边界；不等于上述真实模型用例已经执行。

工具只通过代码模式暴露时，验收提示明确授权使用一次 `functions.exec` 转发。不能将“不要额外调用其它工具”误写成连调用原生工具所必需的包装也禁止；如果模型没有实际尝试 canary，该用例必须失败，修正驱动后另记重验结果。最新真实代码模式对照已使用严格校验器回查通过。
